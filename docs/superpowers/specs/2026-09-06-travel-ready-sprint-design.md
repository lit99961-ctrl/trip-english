# Trip English 旅行可用冲刺设计

## 目标

在扩展其他国家或增加商业化功能之前，把 Trip English 做成学习者能在 iPhone 上安装、每天坚持训练，并能为意大利和瑞士旅行快速提升基础听说能力的产品。

本阶段只追求三个结果：

1. 能独立说出完成酒店、点餐、买票、坐火车和超市购物所需的短句。
2. 能听懂工作人员回答中的时间、价格、地点、确认、否定和变化信息。
3. 能看懂菜单、票面、站台、价签、自助结账屏和收据中的少量关键词。

## 范围与优先级

### 必须交付

- 恢复可从 iPhone Safari 打开的 GitHub Pages 地址，并支持添加到主屏幕。
- 保留现有意大利与瑞士默认课程和所有已有学习进度。
- 首页提供一个约 30 分钟的正式训练入口，以及每天三组、每组约 2 分钟的碎片复习入口。
- 新增通用超市购物任务，覆盖价格、重量、袋子、刷卡、自助结账和收据。
- 强化酒店、餐厅点餐、买票和坐火车的听力回答变化。
- 使用轻量的“观察—猜词—听懂—开口”循环，但不让谜题阻止课程继续。
- 完成手机安装、朗读、麦克风、录音回听、离线学习、续学和备份恢复验收。

### 本阶段不做

- 法国、西班牙、加拿大、新西兰和冰岛内容包。
- 账号、密码、云同步、排行榜、付费或后台管理。
- 相机识别、自由对话大模型或复杂语法课程。
- 复制《巴别塔圣歌》的美术、文字系统、角色、故事或具体谜题。
- 在仓库中加入任何预生成系统语音录音。

## 核心体验

### 首次进入

保留现有 2 分钟、六题起点小游戏。校准只决定提示多少，不给用户贴能力等级标签。完成后进入首页，并明确显示今天的训练入口。

### 30 分钟正式训练

首页的主要操作为“开始今天的 30 分钟训练”。一次正式训练由三个连续的短任务组成：

1. 一个当前到期的复习任务。
2. 一个近期旅行核心任务。
3. 一个新的或尚未完成的课程任务。

若可用任务不足三个，使用已有任务的不同听力回答和角色变化补足。用户每完成一个短任务就保存进度；中途退出后从未完成的位置继续，而不是整段重来。

### 三次 2 分钟复习

首页显示早、中、晚三枚轻量复习卡。每组最多包含三个项目：

- 一个中文提示后的无答案回想。
- 一个工作人员短回答的听力判断。
- 一个标牌、菜单、票面或价签关键词。

完成状态保存在本机。一天内已完成的卡片显示完成，但仍允许再次练习。复习到期顺序沿用现有间隔调度；没有到期内容时，从尚未掌握的核心短语中选择。

## 单个任务的游戏循环

每个核心任务控制在 8–10 分钟，并使用同一套五步循环：

1. **观察场景**：显示简短中文情境、一个真实文本片段和 3–5 个可能相关的英文词。
2. **听工作人员回答**：播放一句短回答，不先显示完整字幕；允许正常和慢速重播。
3. **判断并发现关键词**：二选一或三选一判断核心意思，再从语境确认关键词。
4. **跟读与回听**：显示目标短句，用户跟读、录音并回听自己的声音。
5. **独立办成事**：只显示中文目标和必要的场景参数，用户说出包含功能关键词的表达。

第一次答错增加视觉或上下文线索，第二次答错显示中文关键词，第三次直接显示答案并进入跟读。错误不会锁关，也不会扣除生命或制造失败压力。

选择题只能记为“已练习”。只有无完整英文提示的主动表达，才可能进入“已独立回想”或“已掌握”。

## 核心场景内容

### 酒店

- 用户表达：有预订、确认姓名、房间是否准备好、早餐时间、Wi-Fi 和房卡。
- 工作人员回答至少覆盖：房间已准备好、尚未准备好、早餐时间、需要证件、自助入住位置。
- 重点听懂：ready、not ready、passport、breakfast、floor、key card。

### 餐厅点餐

- 用户表达：要菜单、点这道菜、说明坚果过敏、选择水、买单。
- 工作人员回答至少覆盖：有座位、需要等候、菜品售罄、是否含坚果、still/sparkling water、价格。
- 食物示例分别使用少量意大利和瑞士常见项目，但学习目标始终是简单英语。

### 买票

- 用户表达：单程或往返、人数、时间、座位、是否需要验票。
- 工作人员回答至少覆盖：价格、下一班时间、站台、需要/不需要验票、座位是否预留。
- 票面只展示完成任务所需的最少信息。

### 坐火车

- 复用意大利高铁、米兰至瑞士转乘和瑞士山区交通任务。
- 工作人员回答至少覆盖：正确/错误列车、站台变化、晚点、取消、换乘地点和是否赶得上连接车次。
- 用户必须练习“请慢一点再说”和“请在屏幕/地图上指出”等恢复句。

### 超市购物

- 新任务 ID 为 `supermarket-groceries`，追加到现有旅行任务之后，不能改变原任务 ID 或已保存进度。
- 关键词：price、kilo、bag、card、receipt，并复用 cash、self-checkout、weigh。
- 用户表达：询问价格、按重量购买、需要袋子、刷卡、索取收据。
- 工作人员或机器回答至少覆盖：每公斤价格、需要先称重、是否需要袋子、刷卡失败、收据位置。
- 场景文本包含欧元和瑞士法郎示例，但不要求学习汇率。

## 内容与数据结构

在现有 `Mission` 和 `Exercise` 基础上增加数据驱动的听力情境，不为每个页面写专用逻辑。

每个需要听力训练的任务声明：

- 场景提示和可见文本。
- 3–5 个目标词。
- 至少三条工作人员回答。
- 每条回答的中文意图、关键词和正确判断选项。
- 对应的用户口语目标及功能关键词组。

运行时从当前任务的回答集合中选择一条。播放使用浏览器/设备的语音合成，不保存或分发语音录音。当前回答、提示次数和练习结果随本题事件一起保存，保存重试必须保持同一题和同一回答。

超市任务作为新任务追加；现有进度结构继续兼容。每日训练与碎片复习只保存稳定 ID、日期和完成状态，不保存个人旅行信息。

## 首页与导航

首页保持单列、单手可操作：

1. 顶部显示离线状态和今天的简短鼓励。
2. 第一张主卡显示“开始/继续今天的 30 分钟训练”。
3. 下方显示三张 2 分钟复习卡及完成状态。
4. 再下方显示意大利与瑞士任务地图和当前任务。

底部仍只有首页、急救箱、进度三个入口。正式训练和单个任务使用可恢复的 hash 路由，浏览器返回始终回到首页或上一任务，不离开应用。

## 无声、语音与离线行为

- 所有听力步骤必须提供“显示文字”或无声阅读替代，不要求公共场所播放声音。
- 正常和慢速朗读调用运行时语音；设备不支持时显示可访问错误并允许继续。
- 在线时可以尝试语音识别；失败、超时或离线时自动进入录音回听与自评。
- 核心课程、词典、急救句卡和进度功能必须离线可用。
- 不把运行时语音是否离线可用作为课程通关条件。

## 错误处理

- 进度保存失败时停留在当前题，显示“重试保存”，复用相同事件 ID，不能重复累计口语时间或复习次数。
- 朗读失败只影响声音，不隐藏英文或阻止继续。
- 麦克风拒绝或录音失败时允许切换无声模式和自评。
- 语音识别结果为空、失败或网络断开时不误判失败，改用自评。
- 备份恢复前继续显示日期、课程版本、任务数和口语时长摘要，并由用户明确确认。

## 发布顺序

1. 在私有仓库完成内容、首页和流程修改。
2. 运行单元测试、构建、移动端/桌面端端到端测试及敏感信息扫描。
3. 在本地和浏览器中检查首次进入、正式训练、复习、超市任务和急救箱。
4. 重新公开已清理的仓库，恢复 GitHub Pages。
5. 用 iPhone Safari 完成实机清单；出现发布阻断问题时立即修复，不扩展其他国家。

## 验收标准

- 新用户完成校准后，在三次点击内开始第一次口语练习。
- 首页能开始并恢复一组由三个短任务构成的正式训练。
- 首页有三组最多三个项目的碎片复习，并按当天完成状态展示。
- 酒店、点餐、买票、坐火车和超市任务各有至少三条不同工作人员回答。
- 超市任务覆盖价格、重量、袋子、刷卡、自助结账和收据。
- 所有听力步骤可正常、慢速朗读，也可无声完成。
- 口音、小语法错误和识别不可用不会卡住课程。
- 现有任务 ID 和旧进度继续有效。
- 课程、词典、急救句卡、续学与备份恢复可在离线状态使用。
- 仓库及 Git 历史不包含个人行程、密钥或预生成系统语音录音。
- iPhone 主屏幕安装、单手布局、大字体、麦克风、录音回听和飞行模式检查通过后才视为旅行可用。
